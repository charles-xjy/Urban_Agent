# 折叠卡片与后端 Agent 消息推送渲染逻辑

> 分析对象：`frontend/ui` 前端 + `frontend/graph.py` 后端
> 分析日期：2026-07-28
> 行号基于当前代码状态，修改后可能漂移

## 一、两条推送管线总览

researcher（研究员节点）的「运行中」和「已完成」是**两条并行渲染管线**，对应同一条产出的两种生命周期阶段：

```
后端 frontend/graph.py (researcher 节点)
        │
        ├─【管线 A · 自定义事件】运行中
        │   get_stream_writer() ──> {"type":"research_progress", task_id, topic, stage, detail, round}
        │        │
        │        └─> 前端 onCustomEvent (Stream.tsx:140)
        │              └─> setResearchProgress  ← 纯本地 React state，不进 graph state / checkpoint
        │                    └─> ResearchProgressList / ActiveAgentCard (thread/index.tsx:88 / 111)
        │                          琥珀色转圈 · "运行中"
        │
        └─【管线 B · 消息通道】已完成
            AIMessage(content="【Agent N · topic 执行结果】\n{json}", name="internal")  (graph.py:682-688)
                 │
                 └─> 进入 graph state / checkpoint（持久化）
                       └─> thread/index.tsx 消息过滤 (index.tsx:256) -> AssistantMessage (ai.tsx:402)
                             └─> msgName === "internal" 分支 (ai.tsx:417)
                                   └─> AgentOutputCard (ai.tsx:102)  绿色对勾 · "已完成"
```

**关键交接点**：任务跑完时，后端发一个 `stage: "complete"` 的事件（`graph.py:668`），前端在 `Stream.tsx:157-161` 收到后把该 `task_id` 从 `researchProgress` 删掉 → 运行中卡片消失；同时 `internal` 消息到达 state → 完成卡片接管。

**所以同一份 researcher 产出，先在 A 里「活」着，结束后切到 B 里「定」下来。**

## 二、四种可折叠组件

代码里一共有 4 种可折叠组件，不要混淆：

| 卡片 | 文件:行 | 触发 | 状态 | 数据来源 |
|---|---|---|---|---|
| **`ActiveAgentCard`** | `thread/index.tsx:111` | researcher 运行中 | 琥珀转圈 "运行中" | 本地 state `researchProgress`（管线 A） |
| **`AgentOutputCard`** | `messages/ai.tsx:102` | researcher 完成（`name === "internal"`） | 绿色对勾 "已完成" | 消息 content（管线 B） |
| `ThinkingBlock` | `messages/thinking-block.tsx` | `<think>` 思考过程 | — | 消息 content |
| `ToolResult` 展开 | `messages/tool-calls.tsx:68` | tool 消息 | — | tool message content |

要改的「折叠卡片」大概率是前两个（researcher 的运行中卡 / 完成卡）。它们的折叠态都各自用 `useState(false)` 管理，**互不共享**。

## 三、消息推送的渲染细节

### 管线 A：实时进度（`Stream.tsx`）

- `onCustomEvent` 收到 `research_progress`（`Stream.tsx:149-189`），按 `task_id` 聚合到 `researchProgress`，维护一个 `history[]` 数组。
- 去重逻辑在 `Stream.tsx:165-175`：若 stage+detail 都没变，不追加到 history。
- `researchProgress` 通过 `Object.assign(Object.create(streamValue), { researchProgress })`（`Stream.tsx:221-224`）挂在 stream context 上。
  - **注意它不是 graph state 的一部分**，所以刷新页面 / 切线程不会保留，也不进 checkpoint。
- 渲染入口在 `index.tsx:568-575`：`<ResearchProgressList progress={stream.researchProgress}/>`。
- 当 `isLoading` 但进度为空时，才显示通用 loading 点点（`index.tsx:572-575`）。

### 管线 B：最终卡片（`ai.tsx`）

- 消息过滤（`index.tsx:256-270`）做了两件事：
  1. `name === "internal"` 的消息**强制保留**进主对话流（`return true`）；
  2. 带 `checkpoint_ns` 的子图消息**过滤掉**（不进主流，只算折叠详情）。
     - 这跟 `docs/streamSubgraphs-覆盖问题分析.md` 里记的 bug 相关。
- `AssistantMessage` 里 `msgName === "internal"` 分支（`ai.tsx:417-427`），用正则 `^【(.+?) (执行结果|研究进度)】\n([\s\S]*)$` 拆出 `topic / status / content`，交给 `AgentOutputCard`。
- `AgentOutputCard` 里 `parseAgentCardPayload`（`ai.tsx:64-99`）兼容两种格式：
  - **v2**：JSON 结构化 payload（`graph.py:672` 产出）
  - **v1**：旧纯文本（正则匹配 `• 正在搜索：…` 等）
- v2 会渲染：3 个统计格（执行步骤 / 检索任务 / 有效来源）+ 执行过程时间线 + 检索结果（嵌套 `<details>`）+ 工具结果 + 影像附件 + 研究结论。

## 四、后端产出字段对照

### `research_progress` 事件（管线 A，`graph.py:545-558`）

```python
{
  "type": "research_progress",
  "task_id": task["id"],
  "topic": topic,
  "stage": stage,        # searching / satellite / poi / search_done / search_result / tool_done / tool_result / complete
  "detail": detail,      # 展示文本
  "round": len(progress_msgs) + 1,
}
```

### `internal` 消息（管线 B，`graph.py:672-685`）

```text
【Agent {task_number} · {topic} 执行结果】
{card_payload_json}
```

`card_payload` 结构：

```json
{
  "version": 2,
  "process": ["正在搜索：…", "搜索完成：…（N 条有效结果）", ...],
  "searches": [{ "query": "", "total": 0, "error": "", "results": [...] }],
  "tools": [{ "tool": "web_search", "summary": "…" }],
  "findings": "研究结论 Markdown"
}
```

> **注意**：管线 B 的 `process` 是后端 `progress_msgs` 字符串数组；管线 A 的 `history` 是前端按 stage/detail 聚合的 `{stage, detail, round}` 数组。**两套结构不对齐**——若想让完成卡也带历史进度，需要在 `card_payload` 里把结构对齐。
